# Страховочный офлайн-план («План Б» на случай сбоя VPS/Wi-Fi)

> **Назначение документа:** пошаговый регламент действий для докладчика и команды QA на защите проекта перед экспертами и комиссией («Инносети») при возникновении проблем с внешним интернет-каналом, Wi-Fi в аудитории или сетевыми таймаутами к удалённому VPS (`graphql.rebyte.fun`).

---

## 1. Речевой модуль для комиссии (Что говорить при сбое сети)

Если во время демонстрации браузер показывает `ERR_CONNECTION_TIMED_OUT`, `502 Bad Gateway` или долгую загрузку внешнего сайта:

> *«Уважаемые эксперты, на удалённом хостинге сейчас возникли сетевые задержки внешнего канала связи. Однако архитектура нашего решения изначально проектировалась с учётом требований автономности и катастрофоустойчивости.*  
> *Я мгновенно переключаю демонстрационный контур на локальный резервный стенд (План Б), который поднят на этой машине, полностью изолирован от внешнего интернета и содержит все подтверждённые метрики и работающие компоненты».*

---

## 2. Экспресс-диагностика связи (за 3 секунды)

Для быстрой проверки состояния удалённого и локального стендов выполните команду:

```powershell
coverage-qa offline check
```

В проекте сформирован полностью автономный пакет демонстрационных материалов, который открывается в браузере **двойным кликом прямо из папки** (или с флешки) и не требует запуска Docker, Python или интернета:

- **Адрес файла:** [reports/offline-showcase/showcase.html](file:///C:/Code/GraphQL/GraphQL-Coverage-Proxy-QA/reports/offline-showcase/showcase.html)

### Что содержит офлайн-шоукейс:
1. **Сводная карточка подтверждённых метрик:**

   - **10 из 10** успешных сквозных сценариев магазина
2. **Эталонный интерактивный отчёт приёмки:**

3. **Выгрузки данных в один клик:**

## 4. Вариант «Б»: Полный живой локальный контур на 127.0.0.1

Если комиссия просит вживую понажимать кнопки и увидеть живую работу сервисов:

### Шаг 1. Локальная панель TestLab (QA-панель)

```powershell
coverage-qa panel --port 9020
```
- Откройте: **[http://127.0.0.1:9020/](http://127.0.0.1:9020/)**
- Показывает каталог тестов, запуск сценариев в реальном времени, шаги проверок и историю.

### Шаг 2. Локальная витрина FORMA Demo Shop

**Запуск через Docker Compose (рекомендуется):**
```powershell
docker compose -p gql-commerce-demo -f examples/shop/compose.yaml up -d
```
- Откройте: **[http://127.0.0.1:9110/](http://127.0.0.1:9110/)**
- Каталог, корзина, оформление заказов под Alice (`test-password-2026`), история покупок и API-инспектор.

*Остановка после показа:*
```powershell
docker compose -p gql-commerce-demo -f examples/shop/compose.yaml down
```

### Шаг 3. Локальный запуск E2E автотестов при комиссии

Покажите экспертам реальный запуск браузерного тестирования витрины:

```powershell
coverage-qa test -- tests/e2e/test_shop.py
```
- Playwright в headless-режиме прогонит все 10 сценариев, проверит PostgreSQL и выдаст свежий HTML-отчёт со скриншотами.

## 5. Обновление пакета Плана Б перед защитой

Перед выходом на защиту обновите офлайн-бандл свежими данными:

```powershell
# 1. Прогнать быстрый preflight:
coverage-qa preflight

# 2. Собрать актуальный офлайн-бандл:
coverage-qa offline bundle

# 3. При необходимости запустить локальный сервер презентации:
coverage-qa offline serve --port 9030
```

План Б гарантирует 100% успех защиты вне зависимости от внешних технических обстоятельств.
