# FORMA — пример магазина на GraphQL

В этой папке находятся обе части мини-проекта:

- `api/` — GraphQL API с PostgreSQL: каталог, пользователи, сессии, заказы и остатки.
- `web/` — витрина с корзиной, входом, историей, отменой заказов и API-инспектором.
- `compose.yaml` — единый запуск PostgreSQL, API и витрины.

Все команды ниже выполняются из корня QA-репозитория.

```sh
docker compose -p gql-commerce-demo -f examples/shop/compose.yaml up --build -d --wait
```

Откройте http://localhost:9110/. API: POST http://localhost:9100/graphql.
Для входа выберите Alice, Bob или Admin и нажмите «Войти». Пароль всех вымышленных аккаунтов — `test-password-2026`.

## Показать работу

1. Добавьте клавиатуру и кабель в корзину, измените количество.
2. Войдите как Alice, оформите заказ и скопируйте его ID.
3. Откройте «Мои заказы»: сумма и позиции прочитаны из PostgreSQL.
4. Отмените заказ: статус изменится, остатки вернутся в каталог.
5. В API-инспекторе выберите запрос покупки или отмены. Видны реальные операция, переменные и ответ, секреты скрыты.
6. Войдите как Bob для отдельной истории или Admin для статистики.

Данных реальных пользователей, платежей и доставки нет. БД магазина сохраняется между перезапусками в своём Docker volume.

Остановка с сохранением данных:

```sh
docker compose -p gql-commerce-demo -f examples/shop/compose.yaml down
```

## Автотесты

```powershell
.\.venv\Scripts\coverage-qa test -- tests/e2e/test_shop.py
```

Автотесты поднимают другую БД и другую копию витрины со случайными портами. Их запросы идут через Coverage Proxy и сохраняются в покрытии. Ручной магазин в Compose обращается напрямую к своему API. Результаты появляются в панели http://localhost:9020/ после запуска `coverage-qa panel`.

## Проверка потери ответа при покупке

```powershell
.\.venv\Scripts\coverage-qa test -- tests/e2e/test_shop.py -k retry_after_lost
```

Сценарий выполняет настоящую покупку, имитирует потерю уже успешного ответа и нажимает оформление повторно. В артефактах видно: два HTTP-вызова mutation, один idempotency key, один ID заказа и одно списание. Внедрение сбоя происходит только в изолированном браузерном тесте; обычный магазин не требует специального режима.
