# GraphQL Coverage Proxy — памятка для экспертов

> **Проект команды QualiMeter.** Краткая инструкция по доступу к работающему стенду, демонстрации возможностей и проверке результатов.
>
> Актуальность: **16 ноября 2026 года**. Значения покрытия ниже — снимок демонстрационного прогона, а не постоянная гарантия метрик.

## 3. Что делает проект

GraphQL Coverage Proxy анализирует **фактические** GraphQL-запросы и показывает, какие поля схемы действительно выбирались клиентами.

- Строит интерактивный граф типов, полей и связей по снимку GraphQL-схемы.
- Считает покрытие схемы (`coveredFields / totalFields`) и количество обращений к полям.
- Показывает операции, HTTP-обращения, GraphQL-ошибки и время ответа.
- Разделяет сервисы, версии схемы и прогоны, сохраняя историю результатов в PostgreSQL.
- Применяет роли `viewer`, `analyst`, `operator`, `admin`, сервисные разрешения, cookie-сессии и CSRF.
- Запускает из QA-панели независимые API/интеграционные тесты, а в специальном режиме FORMA — E2E через **рабочий** Coverage Proxy.
- Поддерживает интеграцию с корпоративным **GitLab CI/CD**: режим наблюдения с Quality Gate (JUnit XML + regex) и удалённый запуск пайплайнов из панели TestLab.

**Покрытие — это метрика выполнения полей, а не утверждение, что все бизнес-правила проверены.**

## 4. Демонстрация за 5–7 минут

### A. Посмотреть Coverage (1–2 минуты)

1. Открыть [Coverage](https://graphql.rebyte.fun/coverage/) и войти в `demo_operator`.
2. В списке сервисов выбрать **FORMA Demo Shop**.
3. Выбрать его снимок схемы (в демонстрационном прогоне — короткий ID `da132443`).
4. Открыть активный прогон, например **«FORMA — E2E проверка №1»**.
5. Показать граф, проценты покрытия, вкладки **«Операции»** и **«Обращения»**.

### B. Запустить реальные браузерные проверки (2–3 минуты)

1. Открыть [TestLab](https://graphql.rebyte.fun/qa/) и войти через **отдельный** Basic Auth.
2. Включить **«FORMA · рабочее покрытие»**.
3. В поле UUID вставить идентификатор **активного** прогона FORMA из Coverage (или создать новый активный прогон).
4. Выбрать «Браузерные сценарии» (8 E2E-проверок) и запустить.
5. Показать статусы тестов, HTTP-шаги и детали проверки, а после завершения — сохранённый отчёт.

В этом режиме браузерное приложение отправляет запросы через **рабочий** `/graphql`; QA не создаёт новый Coverage run и **не завершает** выбранный run. Секрет административного API-ключа хранится только на VPS.

### C. Убедиться в изменении покрытия (1–2 минуты)

1. Вернуться к тому же прогону в [Coverage](https://graphql.rebyte.fun/coverage/).
2. Нажать **«Обновить покрытие»**.
3. Сравнить число обращений и набор покрытых полей; посмотреть конкретные операции и фактические запросы.
4. При необходимости завершить прогон **вручную** после показа.

### D. Интеграция с GitLab CI (1 минута)

- В панели TestLab перейти во вкладку **🦊 GitLab CI**.
- Показать готовность к интеграции в пайплайны заказчика:
  - **Вариант А (наблюдение):** готовый `.gitlab-ci.yml`, собирающий процент покрытия по регулярному выражению (`Total coverage: XX.XX%`) и публикующий JUnit XML.
  - **Вариант В (триггер):** удалённый запуск существующего пайплайна компании через GitLab API v4 с мониторингом статуса и привязкой покрытия.

### E. Дополнительный показ

- При сценарии «неверный пароль» GraphQL может вернуть ожидаемую ошибку — её следует отличать от падения автотеста.
- В обычном режиме TestLab остальные тесты работают в **изолированной** инфраструктуре, не меняя рабочую БД Coverage.
- Заказы в E2E создаются и отменяются в **демонстрационном** магазине; не запускайте параллельно ручные операции с теми же товарами во время показа.
- В [публичной витрине FORMA](https://graphql.rebyte.fun/shop/) можно вручную оформить и отменить заказ, затем обновить показатели того же активного прогона в Coverage. Локальная версия Docker без дополнительных настроек обращается к API напрямую и онлайн-покрытие не меняет.

## 5. Магазин FORMA — ручная демонстрация

FORMA Demo Shop — самостоятельный тестовый магазин на GraphQL и PostgreSQL: каталог товаров, поиск, корзина, авторизация, оформление и отмена заказов, история покупок и кабинет администратора. Реальных платежей, доставки и настоящих пользовательских данных нет.

**Онлайн для экспертов:** откройте [https://graphql.rebyte.fun/shop/](https://graphql.rebyte.fun/shop/). Установка и Docker не нужны.

**Локально для разработчиков:** понадобятся Docker с Compose v2 и QA-репозиторий. Из корня клонированного QA-репозитория выполните:

```sh
docker compose -p gql-commerce-demo -f examples/shop/compose.yaml up --build -d --wait
```

| Локальный адрес | Что открывает |
| --- | --- |
| [http://localhost:9110/](http://localhost:9110/) | Витрина магазина (только на компьютере, где запущен Docker) |
| `POST http://localhost:9100/graphql` | GraphQL API магазина |
| [http://localhost:9100/schema.graphql](http://localhost:9100/schema.graphql) | SDL схемы |

**Сценарий проверки магазина (3–5 минут):**

1. Откройте витрину, выберите клавиатуру и кабель, добавьте их в корзину и измените количество.
2. Нажмите **«Оформить заказ»** и войдите под демо-профилем **Alice** (учётные данные приведены в разделе 2; профиль можно выбрать прямо на форме).
3. Подтвердите заказ, сохраните его ID и проверьте сумму и позиции в разделе **«Мои заказы»**.
4. Отмените заказ, убедитесь в смене статуса и восстановлении остатков.
5. В **API-инспекторе** посмотрите GraphQL mutation, переменные, ответ сервера и время запроса. Пароли и токены в нём маскируются.
6. При желании войдите как **Bob**, чтобы увидеть независимую историю заказов, или как **Admin**, чтобы открыть статистику магазина.

**Как магазин связан с покрытием.** Опубликованная витрина `/shop/` отправляет ручные запросы через рабочий Coverage Proxy и учитывает их в отдельном активном прогоне FORMA. После действий в магазине выберите этот прогон в Coverage и нажмите **«Обновить покрытие»**. Для демонстрации автоматических браузерных проверок используйте шаги **4A–4C** и режим TestLab **«FORMA · рабочее покрытие»**. Обычная локальная витрина Docker без дополнительных параметров обращается к своему API напрямую и онлайн-покрытие не меняет.

Остановить локальный магазин, сохранив данные:

```sh
docker compose -p gql-commerce-demo -f examples/shop/compose.yaml down
```

Подробнее: [сценарий магазина и архитектура](examples/shop/README.md) · [тестовый план](docs/test-plan.md).

Отдельная QA-панель показывает статусы пройденных сценариев, количество проверок и отчёты по шагам. Наличие GraphQL-ошибки не эквивалентно провалу теста: есть негативные сценарии, где ошибка **ожидается**.

Метрики пересчитываются после последующих запросов. Текущий результат может отличаться от приведённого примера.

## 7. Что стоит знать перед началом

- Для изменения приватного сервиса аккаунту `operator` необходим **service grant**; роль сама по себе не даёт доступа ко всем сервисам.
- Для QA-панели используется существующий Nginx Basic Auth `alexei` и отдельный пароль. Учётка Coverage `demo_operator` там не авторизует.
- Доступ к VPS по SSH, PostgreSQL и административный `COVERAGE_API_KEY` экспертам для демонстрации **не нужны**.
- Не публикуйте в issues, PR, скриншотах и отчётах реальные пароли.
- После завершения приёмки рекомендуется **отключить временный доступ `demo_operator`**, сменить переданный экспертам пароль QA Basic Auth `alexei` и отозвать временные service grants. Учётку администратора `teamadmin` не передавать.
