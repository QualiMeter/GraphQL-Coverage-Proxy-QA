# FORMA — мини-магазин на нашем GraphQL API

Отдельная витрина демонстрационного магазина: каталог, поиск и категории, карточка товара, корзина с количеством, вход, оформление, история и отмена заказа, профиль, обзор администратора. Цены, остатки, пользователи и заказы берутся из `demo_service` с настоящей PostgreSQL. Статические описания и оригинальные SVG-иллюстрации относятся к оформлению витрины.

## Запуск

Из корня QA-репозитория при работающем Docker:

```powershell
powershell -ExecutionPolicy Bypass -File .\shop.ps1
```

Откройте **http://localhost:9110/**. GraphQL API отдельно доступен на `http://localhost:9100/graphql` (POST). Данные сохраняются в Docker volume между перезапусками. Команда поднимает database, API и витрину; исходники командного backend/frontend не меняются.

Остановка без удаления данных:

```powershell
docker compose -p gql-commerce-demo -f compose.demo.yaml down
```

## Демонстрация за пару минут

1. Выберите товары в каталоге. Mouse недоступна, потому что её фактический stock равен нулю.
2. Откройте корзину и измените количество. Итог вычисляется по текущему каталогу.
3. Нажмите «Оформить заказ». Если вход не выполнен, появится форма входа.
4. Выберите демо-профиль **Alice** и нажмите **«Войти»**. Кнопка профиля заполняет настоящие credentials, а вход выполняется GraphQL mutation.
5. Снова нажмите «Оформить заказ». Появятся ID заказа и сумма, возвращённые сервером. Денег не списывается.
6. Перейдите в «Мои заказы». Заказ прочитан отдельным query из БД. Отмените его и проверьте, что статус изменился, а товары вернулись в каталог.
7. Внизу страницы откройте **API-инспектор**. Выберите вход, создание или отмену заказа: видны операция, переменные, реальный ответ, HTTP-статус и время. Пароль и token замаскированы.

Вход Bob показывает другую историю. Admin открывает в кабинете статистику, полученную через adminStats. В профиле можно изменить имя; новое значение сохраняется в БД.

## Как это связано с тестовым проектом

`tests/test_business_storefront.py` выполняет пять браузерных сценариев:

- каталог, поиск, категории, недоступный товар и корзина без списания;
- покупка нескольких товаров, независимое чтение сохранённого заказа и отмена с возвратом остатков;
- неверный пароль и скрытие секрета в инспекторе;
- кабинет администратора с реальной статистикой;
- отбрасывание задержанного ответа заказов после выхода.

Тестовый маршрут: **браузер → витрина → Coverage Proxy → commerce API → PostgreSQL**. Каждый сценарий получает отдельный coverage run. В отчёт попадают запросы браузера, реальные серверные поля, скриншот и Playwright trace. Проверки сохранения выполняются отдельными HTTP-запросами. Очистка отменяет только заказы, созданные сценарием. Обычный демо-магазин и его постоянная БД тестами не сбрасываются.

```powershell
.\.venv\Scripts\python run_tests.py --suite business --local -- -k storefront
```

В панели `http://localhost:9020/` нажмите «Обновить список» и найдите **«Магазин:»**. Каждый сценарий можно выбрать отдельно. Ссылка на панель также есть внизу витрины.

## Разработка без пересборки Docker

При уже запущенном API:

```powershell
.\.venv\Scripts\python mini_shop/server.py --port 9111
```

Откройте `http://localhost:9111/`. Изменения HTML/CSS/JS читаются с диска. Перезапуск API не требуется.

Витрина использует небольшой same-origin сервер: браузер обращается к `/api/graphql`, сервер пересылает запрос на `SHOP_GRAPHQL_URL`. По умолчанию это `http://127.0.0.1:9100/graphql`. Адрес управляется окружением сервера, не телом запроса браузера. Только Authorization передаётся от браузера; Cookie не пересылаются.

Для тестового режима через прокси задаются серверные `SHOP_COVERAGE_API_KEY`, `SHOP_COVERAGE_RUN_ID` и `SHOP_GRAPHQL_URL=<proxy>/graphql`. Схема и running-прогон должны соответствовать commerce API. Автотесты настраивают это сами. Ключ покрытия никогда не отдаётся браузеру. В обычном Docker-запуске магазин подключён напрямую к своему API; проценты покрытия в витрине не рисуются.

Корзина и ключ повторной отправки хранятся в localStorage; токен демо-сессии — в sessionStorage текущей вкладки. При сетевой ошибке корзина и idempotency key сохраняются, чтобы ручной повтор не создавал второй заказ. Журнал инспектора хранит последние 100 обращений только в памяти вкладки.

Товары и аккаунты вымышленные. Реальных платежей и доставки в этом примере нет.
