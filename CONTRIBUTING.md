# Работа в команде

## Ветки и объединение

Репозиторий QA самостоятельный. Начальная поставка находится в `feat/qa-platform-and-demo-shop`; основной backend и frontend остаются в своих репозиториях. После просмотра изменений создайте pull request этой ветки в `main`, дождитесь зелёного CI и объедините его по правилам команды.

Для следующих задач создавайте ветки от актуального `main`, например `test/order-validation`. Коммитьте сценарии, фикстуры, документацию и lock-файл, если изменились зависимости. Не коммитьте `.venv`, `.browsers`, `.env`, `reports`, дампы БД и runtime-логи; они исключены `.gitignore`.

## Свой сценарий

См. [docs/writing-tests.md](docs/writing-tests.md). Файлы `tests/api/shop/test_*.py` автоматически входят в business/all. Проверки QA-инструментов добавляйте в `tests/platform/`, браузерные — в `tests/e2e/`. Группа определяется папкой, а не префиксом имени. `@pytest.mark.case` задаёт название в панели.

Используйте `business` для API-сценариев и fixture `storefront` для browser E2E. Ожидания вычисляйте независимо, успешную mutation проверяйте отдельным чтением. Проверяйте отказ, права, состояние после ошибки, идемпотентность и очистку собственных данных.

## Проверка перед PR

```powershell
.\.venv\Scripts\coverage-qa test --suite all --local
```

При изменении только одного сценария начните с `-- -k <часть_имени>`, затем выполните подходящие связанные проверки. Приложите backend commit (`git -C ../GraphQL-Coverage-Proxy-Beckend rev-parse HEAD`), команду, результат и известные ограничения. HTML/trace отдавайте как CI artifacts, не добавляйте в Git.

## Выбор версии backend в CI

При обычном push/PR проверяется совместимый Backend SHA, закреплённый в `.github/workflows/tests.yml`; GitLab использует тот же SHA из `.gitlab-ci.yml`. Обновляйте оба pin согласованно. Для воспроизводимой проверки используйте Actions → API integration tests → Run workflow → `backend_ref`: ветку, tag или полный commit SHA. Checkout backend публичный; для приватного форка установите secret `COVERAGE_BACKEND_TOKEN` с правом чтения этого репозитория. Сам секрет не хранится в коде.

QA не меняет исходники командного backend. Скрипт `tools/prove_coverage_detection.py` намеренно вносит дефект только во временную копию и проверяет, что тест его обнаружил.

## Согласование контрактов

Перед изменением API-сценариев сверяйте [документ совместимости](docs/backend-compatibility.md). Проверенный frontend пока использует локальный store; подключение основного UI выполняется в его репозитории. QA не выдаёт demo E2E за E2E основного frontend. В PR указывайте backend commit из отчёта, а не только название ветки.
